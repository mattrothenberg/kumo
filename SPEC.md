# Figma UI Kit Generation Spec

> Generate production-quality Figma components from the Kumo codebase, with code as the single source of truth.

## Overview

Build a Figma plugin that generates UI kit components by reading component definitions from `@cloudflare/kumo`. The plugin runs inside Figma and creates ComponentSets with proper variants, auto-layout, and variable bindings.

### Goals

1. Provide designers with a complete, code-accurate Figma UI kit
2. Maintain code as the single source of truth
3. Bind components to existing `kumo-colors` design tokens
4. Support destructive sync (purge and recreate on each run)

### Non-Goals

- Bidirectional sync (Figma → code)
- Icon library generation (placeholder icons for now)
- Shipping plugin with npm package (dev tooling only)

```
┌─────────────────────────────────────────────────────────────┐
│                     Kumo Codebase                           │
├─────────────────────────────────────────────────────────────┤
│  component-registry.json    →  Component specs (props,      │
│                                variants, defaults)          │
│                                                             │
│  button.tsx, badge.tsx      →  Opacity modifiers            │
│                                (bg-primary/70, etc.)        │
│                                                             │
│  kumo-colors (Figma)        →  Base color variables         │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                     Figma Plugin                            │
├─────────────────────────────────────────────────────────────┤
│  1. Parse component registry                                │
│  2. Extract opacity modifiers from source files             │
│  3. Generate opacity-* variables in kumo-colors             │
│  4. Purge existing generated components                     │
│  5. Create ComponentSets with variants                      │
│  6. Bind fills/strokes to variables                         │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                     Figma Output                            │
├─────────────────────────────────────────────────────────────┤
│  kumo-colors collection:                                    │
│    - surface, primary, error, ... (from code)               │
│    - opacity-primary-70, opacity-error-50 (Figma-only)      │
│                                                             │
│  Components page:                                           │
│    - Button ComponentSets (by variant × size)               │
│    - Badge ComponentSets (by variant)                       │
└─────────────────────────────────────────────────────────────┘
```

## Sync Strategy

**Destructive sync** - purge and recreate on each run.

1. Delete all components in the target page/section
2. Delete all `opacity-*` variables from `kumo-colors`
3. Regenerate opacity variables from source analysis
4. Regenerate all components fresh

This ensures code-Figma parity and avoids drift from manual edits.

## Variable Strategy

### Base Variables (from existing token sync)

Already synced via `sync-tokens-to-figma.ts`:

- `surface`, `surface-2`, `surface-3`
- `primary`, `secondary`, `error`, `alert`, `info`
- `border`, `border-2`, `muted`, `disabled`
- etc.

### Derived Opacity Variables (Figma-only)

Generated by parsing component source files for Tailwind opacity modifiers:

| Source Pattern    | Generated Variable     | Value                 |
| ----------------- | ---------------------- | --------------------- |
| `bg-primary/70`   | `opacity-primary-70`   | primary @ 70% alpha   |
| `bg-primary/50`   | `opacity-primary-50`   | primary @ 50% alpha   |
| `bg-error/70`     | `opacity-error-70`     | error @ 70% alpha     |
| `bg-secondary/50` | `opacity-secondary-50` | secondary @ 50% alpha |

**Namespace:** `opacity-` prefix distinguishes Figma-only variables from code tokens.

**Implementation:**

1. Regex scan component files for patterns: `(bg|text|border|ring)-(\w+)/(\d+)`
2. Deduplicate across all components
3. Create variables with base color + opacity modifier

## Component Specifications

### Button

#### Structure (Split Pattern)

Organized by variant, then size. Matches UI Prep design system pattern.

```
Page: Components

Section: Primary
├── Button Primary XS      (ComponentSet)
├── Button Primary SM      (ComponentSet)
├── Button Primary Base    (ComponentSet)
├── Button Primary LG      (ComponentSet)

Section: Primary Icon
├── Button Primary Icon XS   (ComponentSet, Shape variant)
├── Button Primary Icon SM   (ComponentSet, Shape variant)
├── Button Primary Icon Base (ComponentSet, Shape variant)
├── Button Primary Icon LG   (ComponentSet, Shape variant)

Section: Secondary
├── Button Secondary XS
├── Button Secondary SM
├── Button Secondary Base
├── Button Secondary LG

Section: Secondary Icon
├── Button Secondary Icon XS
├── Button Secondary Icon SM
├── Button Secondary Icon Base
├── Button Secondary Icon LG

[Repeat for: Ghost, Destructive, Secondary-Destructive, Outline]
```

**Total:** 6 variants × 4 sizes × 2 types (text/icon) = 48 ComponentSets

#### Variant Properties

**Text Buttons (e.g., "Button Primary Base"):**

| Property      | Type          | Values                                    | Default     |
| ------------- | ------------- | ----------------------------------------- | ----------- |
| State         | VARIANT       | Default, Hover, Active, Disabled, Loading | Default     |
| Label         | TEXT          | -                                         | "Button"    |
| Icon          | BOOLEAN       | true, false                               | false       |
| Icon Position | VARIANT       | left, right                               | left        |
| ↪ Icon       | INSTANCE_SWAP | (placeholder)                             | Placeholder |

**Icon Buttons (e.g., "Button Primary Icon Base"):**

| Property | Type          | Values                                    | Default     |
| -------- | ------------- | ----------------------------------------- | ----------- |
| State    | VARIANT       | Default, Hover, Active, Disabled, Loading | Default     |
| Shape    | VARIANT       | square, circle                            | square      |
| ↪ Icon  | INSTANCE_SWAP | (placeholder)                             | Placeholder |

#### Size Specifications

From `KUMO_BUTTON_VARIANTS.size`:

| Size | Height | Padding X | Padding Y | Gap | Border Radius | Font Size   |
| ---- | ------ | --------- | --------- | --- | ------------- | ----------- |
| xs   | 20px   | 6px       | -         | 4px | 2px (sm)      | 12px (xs)   |
| sm   | 26px   | 8px       | -         | 4px | 6px (md)      | 12px (xs)   |
| base | 36px   | 12px      | -         | 6px | 8px (lg)      | 16px (base) |
| lg   | 40px   | 16px      | -         | 8px | 8px (lg)      | 16px (base) |

#### Icon Button Size Specifications

From `KUMO_BUTTON_VARIANTS.compactSize`:

| Size | Dimensions  |
| ---- | ----------- |
| xs   | 14px × 14px |
| sm   | 26px × 26px |
| base | 36px × 36px |
| lg   | 40px × 40px |

#### State Styling (Primary variant example)

| State    | Fill Variable        | Text  | Additional                |
| -------- | -------------------- | ----- | ------------------------- |
| Default  | `primary`            | white | -                         |
| Hover    | `opacity-primary-70` | white | -                         |
| Active   | `opacity-primary-70` | white | -                         |
| Disabled | `opacity-primary-50` | white | opacity: 50% on component |
| Loading  | `primary`            | white | Loader component visible  |

#### Variable Bindings

Each component variant binds to variables:

```typescript
// Primary Default
fills: [{ type: "VARIABLE_ALIAS", id: variables["primary"] }];
// Text
fills: [{ type: "SOLID", color: white }];

// Primary Hover
fills: [{ type: "VARIABLE_ALIAS", id: variables["opacity-primary-70"] }];

// Secondary Default
fills: [{ type: "VARIABLE_ALIAS", id: variables["secondary"] }];
strokes: [{ type: "VARIABLE_ALIAS", id: variables["border"] }];
```

## Component Internal Structure

### Button (Text) - Auto Layout

```
Button [COMPONENT] - Horizontal, Center aligned
├── Icon Instance [INSTANCE] - conditional visibility
├── Label [TEXT] - "Button"
├── Icon Instance [INSTANCE] - conditional visibility (right position)
└── Loader [INSTANCE] - conditional visibility (loading state)
```

**Auto Layout Settings:**

- Direction: Horizontal
- Alignment: Center (both axes)
- Padding: Per size spec
- Gap: Per size spec
- Sizing: Hug contents (min-width: varies by size)

### Button (Icon) - Auto Layout

```
Button Icon [COMPONENT] - Horizontal, Center aligned
└── Icon Instance [INSTANCE]
```

**Auto Layout Settings:**

- Direction: Horizontal
- Alignment: Center (both axes)
- Fixed size: Per compactSize spec

### Badge - Auto Layout

```
Badge [COMPONENT] - Horizontal, Center aligned
└── Label [TEXT] - "Badge"
```

**Auto Layout Settings:**

- Direction: Horizontal
- Alignment: Center (both axes)
- Padding: 8px horizontal, 2px vertical
- Sizing: Hug contents

## Plugin API Usage

### Key APIs

```typescript
// Create components
figma.createComponent();
figma.createComponentSet();
figma.combineAsVariants();

// Create shapes
figma.createFrame();
figma.createRectangle();
figma.createText();

// Variables
figma.variables.createVariable();
figma.variables.getVariableCollectionById();
figma.variables.getLocalVariableCollections();

// Variable binding
node.setBoundVariable("fills", variable);
```

### Variable Binding Example

```typescript
// Get or create variable
const collection = figma.variables
  .getLocalVariableCollections()
  .find((c) => c.name === "kumo-colors");

const primaryVar = figma.variables
  .getLocalVariables()
  .find((v) => v.name === "primary");

// Bind to fill
const button = figma.createComponent();
const fill: SolidPaint = {
  type: "SOLID",
  color: { r: 1, g: 1, b: 1 },
  boundVariables: {
    color: { type: "VARIABLE_ALIAS", id: primaryVar.id },
  },
};
button.fills = [fill];
```

## Testing & Validation

### Manual Checks

1. All ComponentSets appear in Assets panel
2. Variant dropdowns work correctly
3. Component properties are editable
4. Variable bindings update with mode changes (Light/Dark)
5. Auto-layout resizes correctly with content

### Automated Validation

The plugin should log:

- Number of components created
- Number of variables created
- Any binding failures
- Comparison with expected counts
